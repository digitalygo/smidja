# Revamp implementation status

This is an incremental draft, not a deployment or a declaration that every acceptance criterion is complete.

## Implemented in this branch

- Authenticated single-owner manager and embedded browser UI, JSONL sessions/tasks/tool receipts, restart recovery with explicit uncertainty.
- Envai ATP v3 adapter, request signatures and native delegation/delivery/classification contracts. Workflow phase completion waits for the delegated **job**, not its first turn acknowledgement.
- Sequential taskboard with exact phase outputs, classifier-only retry and blocked-phase resume; native cancellation acknowledgement and uncertain cancellation remain distinguishable.
- Generic OS-permission machine tools, outgoing authenticated clients, online/offline inventory, text editing with conflict checks and Git diff.
- Public/private package sources, verified immutable releases, periodic updates, pinned workflow teams and tools, retained execution routes across restart, client-owned package capabilities and lazy skills.
- Private team/workflow/extension proposals, owner approval, revision checks and recoverable archive. Approved manager/client extensions execute with explicitly referenced environment variables. Client activation propagates authenticated revisioned controls, remains visible while pending/offline and rejects new stale calls immediately. Existing actions may finish before a serial client applies archive.
- CEO team discovery/delegation, workflow and client tools; client namespaces distinguish otherwise identical teams/tools.
- Strict configured root model admission for CEO and team/workflow delegates, targeting Envai PR #56 commit c907371b252244cf7a2475d6326e90a28da82880.
- Read-only four-phase PR review with manual API/CEO/UI entry, pinned base/head SHAs, full diff and exact-head CI evidence, focus and optional repository/organization polling using the same taskboard and deduplication. No automatic code execution or GitHub publication.
- Independent code review and offline race tests. CI includes changed-code coverage gates, four build targets, mocked DOM checks and a sandboxed browser smoke job.

## Verification evidence and limits

The eleven new Go packages pass offline race tests with package statement coverage above 85%. The changed-executable-block gate also includes the new CLI code (above 80%). Exact percentages are generated by CI rather than treated as permanent promises.

A full legacy `go test ./...` was attempted after replacing unmocked public catalog requests with deterministic test-only fixtures. With an isolated writable HOME, remaining failures involved legacy PTY/theme/socket behavior and an MCP timing test. They were not hidden, skipped or counted as passing. Targeted new CLI tests passed separately.

The Node mocked-DOM UI suite passes locally. Actual Chromium rendering was blocked by the local environment; the dedicated CI browser job is the verification path and its result must be inspected before claiming rendered UI validation.

No live model inference, credentials provisioning, deploy, merge or repository archival occurred while producing this draft.
